# 05 — Mini-project 1: Business Dashboard

The first checkpoint. Everything from topics 01-04 (LESSON 1-13), in your own public
repository.

There are no lessons in this folder and nothing to run here. The work happens in a new
project beside this course.

## Path

**1. Read [PUBLISHING_GUIDE.md](../PUBLISHING_GUIDE.md)** — once, properly, before you
start. Where the folder goes, how to scaffold it, the commit loop, what the README needs.

**2. Read [mini-project.md](mini-project.md)** — the brief. Core is the project; Bonus is
optional and skipping all of it still leaves you finished.

**3. Build it.** Small commits, each leaving the page working.

**4. Have it reviewed** — paste `review-prompt.txt`, the brief, and your code into a new AI
session. If you get stuck while building instead, `ai-prompt.txt` is the one that guides
without giving answers.

## What makes this one different from an exercise

Every exercise so far had the file waiting for you and a solution beside it. This starts
from an empty folder, and there is no solution to look at — because there are many right
answers and the decisions are now yours.

## The thing people get wrong here

They try to avoid the repetition.

You do not have props yet, so four KPI cards means four hand-written cards. That is
deliberate, it is stated in the brief, and working around it with something from a later
topic defeats the point. Topic 6 exists to remove this exact pain, and it lands properly
only if you have felt it first.

Factor out the shared **shape** with `children`. Leave the repeated **content** alone.
